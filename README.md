# stem-split

Простое настольное приложение для разделения аудио на стемы: вокал, ударные, бас и остальное. Написано на Rust с интерфейсом на egui. Нейросеть работает локально, файлы никуда не отправляются.

> **Статус:** бэкенд проверен на целевой машине; готовы каркас приложения и работа с аудио — чтение файлов, приведение к 44.1 кГц, запись WAV. Разделять аудио приложение ещё не умеет. Ход работ — в [docs/PLAN.md](docs/PLAN.md).

## Что будет уметь первая версия

- Выбрать аудиофайл: MP3, FLAC, WAV, OGG, M4A.
- Выбрать, куда сохранить результат. По умолчанию — рядом с исходным файлом.
- Выбрать модель:

  | Модель | Стемы | Когда выбирать |
  |---|---|---|
  | `htdemucs` | ударные, бас, остальное, вокал | По умолчанию, самая быстрая |
  | `htdemucs_ft` | те же | Качество немного выше, работает примерно в 4 раза дольше |
  | `htdemucs_6s` | те же, гитара и пианино | Когда нужны гитара и пианино отдельно |

- Показать прогресс, отменить обработку.
- Получить файлы вида `song.vocals.wav`, `song.drums.wav` (WAV, 32-битный float, 44.1 кГц).

Ограничения: моно и стерео, длительность до 3 часов. У файлов M4A (AAC) результат может начинаться на 20–50 мс позже, чем исходник в других программах: используемый декодер не убирает задержку кодировщика.

Модель скачивается при первом использовании и сохраняется в кэше: `htdemucs` — 169 МБ, `htdemucs_6s` — 110 МБ, `htdemucs_ft` — 675 МБ.

## Как это устроено

Инференс идёт через [ONNX Runtime](https://onnxruntime.ai/) на моделях [HTDemucs](https://github.com/facebookresearch/demucs) в виде [ONNX-экспорта](https://huggingface.co/HRSadeghi/demucs-onnx). На Windows используется видеокарта через DirectML, при её отсутствии — процессор. Python и ffmpeg не нужны.

На тестовой машине (Ryzen 5 2600, GTX 1660 SUPER) фрагмент в 7.8 секунды обрабатывается за 0.3 с на видеокарте и за 3 с на процессоре.

Подробности — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Требования

- Windows 10 или 11, 64 бита. Код пишется переносимым, но другие системы пока не проверяются.
- Для ускорения — видеокарта с поддержкой DirectX 12. Без неё обработка идёт на процессоре и занимает больше времени.
- Для сборки — Rust 1.96 или новее.

## Сборка и запуск

```sh
cargo run --release
```

## Разработка

Перед коммитом должны проходить без предупреждений:

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Репозиторий — workspace из двух крейтов: `crates/core` (конвейер разделения, без GUI) и `crates/app` (окно на egui). В `spikes/` лежат отдельные пакеты-эксперименты, в сборку приложения они не входят.

Правила кода описаны в [docs/GUIDELINES.md](docs/GUIDELINES.md). Коротко:

- никаких `unwrap`, `expect`, `panic!` и индексации, способной упасть;
- инварианты выражаются типами, чтобы ошибки ловил компилятор;
- `unsafe` запрещён.

Эти правила закреплены линтами в [Cargo.toml](Cargo.toml).
