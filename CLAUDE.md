# stem-split

Настольное приложение на Rust и egui для разделения аудио на стемы. Инференс — ONNX Runtime (`ort`) на моделях HTDemucs, GPU через DirectML с откатом на CPU.

Перед работой с кодом прочитай:

- [docs/GUIDELINES.md](docs/GUIDELINES.md) — обязательные правила кода;
- [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — структура, типы, алгоритм, принятые решения;
- [docs/PLAN.md](docs/PLAN.md) — план по этапам, текущий статус и результаты завершённых этапов.

## Жёсткие правила

- Никаких `unwrap`, `expect`, `panic!`, `todo!`, `unreachable!`, индексации `a[i]` и срезов строк. Это касается и тестов: тесты возвращают `Result` и используют `?`.
- Инварианты выражаются типами: newtype с приватным полем и проверяющим конструктором, `enum` вместо флагов, `NonZero*`, отдельные типы для этапов конвейера. Сначала ищи способ сделать ошибку некомпилируемой, и только потом — проверку в рантайме.
- В `match` по перечислениям проекта нет ветки `_ =>`. Перечисление, по которому нужен перебор, объявляется через `closed_enum!` (экспортируется из ядра) и получает `ALL`.
- Ошибки — `enum` через `thiserror`. Без `anyhow`, `Box<dyn Error>` и `String` в сигнатурах ядра. Отмена — не ошибка.
- `unsafe` запрещён.
- Исключение из линта — только `#[expect(lint, reason = "...")]`. Набор линтов в `Cargo.toml` не ослаблять без явной просьбы.
- Поток UI не блокируется: ввод-вывод, сеть и инференс — только в рабочем потоке.
- Крейт ядра не зависит от `egui`, `eframe` и `rfd`.

## Язык

- Идентификаторы, комментарии, doc-комментарии, сообщения коммитов — на английском.
- README и `docs/` — на русском.
- Интерфейс — на английском и русском. Все строки идут через `view::text`: по модулю на язык (`text::en`, `text::ru`) с исчерпывающим `match`. Новая строка добавляется сразу во все языки, иначе код не соберётся.

## Проверка перед завершением задачи

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Пакеты в `spikes/` в workspace не входят: те же команды запускаются в каталоге пакета.

Тесты, которым нужны сеть, видеокарта или файлы моделей, помечены `#[ignore]` и запускаются вручную с `-- --ignored`. Полный сценарий без окна — пример `separate` в `crates/core/examples`.

Сверка с Python-версией Demucs исключена из плана решением владельца проекта: не предлагать и не выполнять её.

## Документация

При изменении решения, структуры или набора зависимостей обновляй `docs/ARCHITECTURE.md` в том же изменении. При завершении этапа отмечай его в `docs/PLAN.md` и записывай туда результаты.
